# Dispute Bank Statement Requirements

> Source: User conversation in Cursor
> Collected: 2026-05-22
> Published: Unknown

Original request:

При закрытии споров трейдерами и для администратора, если администратор хочет закрыть спор, нужно уметь закрыть спор. Имеется в виду отклонение спора. Принятие спора уже понятно.

Отклонение спора: сейчас система просит указать причину, но этого недостаточно. Теперь нужно уметь указать выписку. Когда админ или трейдер отклоняет спор, он не только указывает причину отклонения, но и обязан загрузить выписку по карте.

Выписка — это информация по переводу по карте. Требования: размер до 5 МБ, формат картинки или PDF, как у host-to-host API и по аналогии с валидацией чеков выплат. Оба поля обязательны.

В модальном окне со спорами, когда спор был отклонён, должна появиться новая строка ниже «Квитанция». Она отображается примерно в таком же стиле, но кнопка имеет цвет Accent и называется «Выписка». По нажатию открывается выписка, которую загрузил пользователь при отклонении спора.

Clarifications:

1. Название `bank_statement` подходит.
2. Любая причина хранится как текст, как сейчас. Пресеты существуют только на фронтенде для удобства.
3. Причина выбирается через dropdown. Доступны фиксированные пресеты:
   - неверные реквизиты;
   - фейковый чек;
   - возврат платежа (карта заблокирована или достигнут лимит по карте).
4. Если ни один preset не подходит, пользователь выбирает «Другая причина» и вводит свой текст.
5. Preset фиксированный; нельзя редактировать текст выбранного preset. Кастомный текст доступен только через «Другая причина».
6. Максимальная длина итоговой причины — 120 символов. Пользователь должен визуально видеть, сколько символов осталось.
7. Выписка обязательна при отклонении спора через интерфейс приложения для любого пользователя, у которого есть функционал отклонения: трейдер, админ, support, analyst.
8. Выписка видна тем же пользователям, которым видна квитанция.
9. Каскадные споры полностью вне scope. Работа только с `Order` и `Dispute`.
10. Старые отклонённые споры без выписки показывают «Нет файла». Выписка обязательна только при новых отклонениях. Если старый спор снова открыт и потом отклоняется, выписка нужна.
11. При повторном отклонении причина и выписка перезаписываются.
12. API не меняется и не затрагивается.
13. Админский интерфейс может использовать существующий общий endpoint отклонения, так как UI единый.
